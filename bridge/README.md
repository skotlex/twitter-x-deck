# 이미지 번역 브리지

사진 속 글자를 번역하는 기능은 이 PC 에 깔린 `codex` · `claude` 명령을 빌려 씁니다.
확장은 파일도 프로세스도 만질 수 없어서, 그 사이를 잇는 작은 서버가 하나 필요합니다.

별도 API 키가 필요하지 않습니다. 두 명령이 이미 로그인해 둔 **구독 계정**을 그대로 씁니다.

## 실행

```bash
npm run bridge
```

이게 전부입니다. 덱의 **설정 › 번역** 을 켜면 알아서 찾아옵니다 — 붙여넣을 열쇠도, 맞춰야 할
포트도 없습니다.

포트는 8765 부터 비어 있는 자리를 골라 앉습니다. 그 번호가 다른 프로그램에게 잡혀 있거나
(윈도우라면) 시스템이 미리 예약해 둔 구간이면 다음 번호로 넘어가고, 확장도 같은 범위를 훑어
찾아옵니다. 시작 번호를 옮기고 싶으면 `XDECK_BRIDGE_PORT` 를 지정합니다.

## 두 엔진의 차이

| | codex | claude |
| --- | --- | --- |
| 결과 | 번역된 **이미지** | 원문과 번역 **텍스트** |
| 걸리는 시간 | 30초 ~ 1분 남짓 | 수 초 |
| 어울리는 사진 | 포스터·만화처럼 배치가 뜻을 갖는 것 | 대부분의 스크린샷과 짧은 문구 |

`claude` 는 이미지를 만들지 못합니다. 번역된 그림이 필요하면 `codex` 를 고르세요.

`codex` 가 다시 그린 이미지는 원본을 그대로 둔 채 글자만 바꾼 것이 아니라 새로 그린
것입니다. 잔글씨나 로고가 뭉개질 수 있어, 덱에서는 원본과 번역본을 오갈 수 있게 해 둡니다.

## 안 될 때

- **브리지를 찾지 못했습니다** — 브리지가 떠 있는지 확인합니다. 8765 부터 16칸 안에
  자리를 잡지 못했다면 콘솔에 그 사정이 찍혀 있습니다.
- **`~/.codex/config.toml` 을 codex 가 읽지 못합니다** — 메시지에 적힌 항목을 그 파일에서
  고칩니다. 값 하나가 어긋나면 codex 는 아예 뜨지 않습니다. 남의 설정 파일을 말없이
  고치지 않으므로 브리지는 무엇이 문제인지만 알려줍니다.
- **로그인이 필요합니다** — 설정 화면의 로그인 단추를 누르면 콘솔 창이 하나 뜹니다.
  거기서 절차를 마친 뒤 **상태 다시 확인** 을 누릅니다.

## 누가 부를 수 있나

열쇠를 주고받지 않습니다. 대신 이렇게 좁혀 둡니다.

- `127.0.0.1` 에만 묶입니다. 같은 망의 다른 기기는 들어올 수 없습니다.
- 요청에 `x-deck-bridge` 헤더가 있어야 합니다. 웹페이지가 이 헤더를 붙이려는 순간 브라우저가
  먼저 예비 요청(preflight)을 보내는데 브리지는 그것을 허락하지 않으므로, 본 요청 자체가
  나가지 못합니다. 확장은 호스트 권한이 있어 그 검사를 거치지 않습니다.
- 사이트 출처(`http://` · `https://`)가 붙은 요청은 받지 않습니다.
- 응답에 CORS 허가를 붙이지 않아, 웹페이지는 답을 읽을 수도 없습니다.

이 PC 에서 도는 프로그램은 무엇이든 이 조건을 흉내 낼 수 있습니다. 다만 열쇠를 파일에 두던
예전 방식도 같은 처지였습니다 — 그 파일을 읽으면 그만이었고, 대신 사용자에게 붙여넣기라는
단계를 하나 얹었을 뿐입니다.

## 그 밖에

번역은 한 번에 하나씩 돕니다. 결과 이미지는 "무엇이 새로 생겼는지" 로 찾기 때문에
동시에 돌리면 서로의 결과를 집어갑니다.
